# تقرير الجاهزية النهائي — Alhraj Plus

**الحالة:** تنفيذ محلي مكتمل لخطوات الخطة القابلة للتحقق، مع **عدم منح موافقة نشر إنتاجي نهائية** حتى إغلاق الحواجز الموضحة في هذا التقرير.

## ملخص التنفيذ

تم تنفيذ الخطة عبر المراحل الثلاث عشرة بالتسلسل، مع مراجعة لاحقة لكل مرحلة وإعادة اختبار المكونات القابلة للتشغيل محليًا. شملت التغييرات طبقات Backend وWeb وMobile، وأضيفت اختبارات حتمية لعقود الأمان والبلد والوسائط والمحفظة والذكاء الاصطناعي والخصوصية.

| مجال التنفيذ | ما تم إنجازه |
|---|---|
| صلاحيات الإدارة وMFA | فُرضت حالة MFA المسجلة والمتحقق منها على مسارات الإدارة في الإنتاج، مع توجيه مستخدم الإدارة لمسار الأمان عند الحاجة ومنع الاعتماد على البريد الإلكتروني كصلاحية. |
| عزل الدولة | تم توحيد حارس الدولة النشطة وتطبيقه على الإعجابات والمفضلة والمزادات والتنبيهات والتعليقات وعلاقات السوق الحساسة. |
| الإعلانات والوسائط | أضيف تحقق خادمي من HTTPS والنوع والعدد وملكية مسارات Cloudinary لوسائط الإعلان. |
| التواصل والإشعارات | استكملت وجهة saved search في Mobile، وفُرضت سياسة البلد على التعليقات، مع استمرار الروابط العميقة الداخلية الآمنة. |
| المكالمات | راجعت عقود signaling والمشاركين والحظر وانتقال الحالات؛ يبقى اختبار الصوت/الكاميرا الفعلي على الأجهزة مطلوبًا. |
| الاقتصاد | قويت عمليات المحفظة بمفاتيح idempotency وفهارس دائمة وبحارس إدارة مع MFA، مع فصل Cash Wallet عن Coins. |
| الذكاء الاصطناعي | أصبحت حدود اليوم والشهر وRPM وTPM مطبقة قبل التدوير وليست مجرد إعدادات معروضة، وأضيفت فهارس وسجلات استخدام شهرية. |
| تصميم Web/Mobile | أضيف لون مستقل لشريط التنقل من الإدارة مع fallback للون الأساسي، وحُدّث شريط Web ليقارب شريط Mobile الكبسولي ذا الفتحة والزر المركزي، وأضيفت تحسينات قارئات الشاشة. |
| الخصوصية وSEO | أزيل منع التكبير في viewport، وأزيلت معرفات متجر تطبيقات تجريبية، وأصبح طلب حذف الحساب idempotent مع بقاءه طلب مراجعة لا حذفًا فوريًا. |
| المقارنة التنافسية | قورنت الميزات العامة مع منصات إعلانات خليجية دون نسخ تجربة ملكية؛ لم تضف ميزات ظاهرية مكررة. الشحن/الدفع الموثوق سُجلا كتكاملات خارجية لازمة لا كواجهات وهمية.[1] [2] [3] |

## حواجز النشر الإلزامية

| الأولوية | الحاجز | الدليل أو الأثر | الإجراء المطلوب |
|---|---|---|---|
| حرج | تبعيات Web ذات ثغرات معلنة | `yarn audit`: 7 عالية و11 متوسطة و3 منخفضة، ويرتبط جزء منها بسلسلة `react-scripts@5.0.1` | ترقية موجهة في فرع مستقل، ثم إعادة build/tests/audit؛ لا تستخدم إصلاحًا قسريًا غير مختبر. |
| حرج | أسرار وإعدادات نشر ناقصة | `cloudbuild.yaml` ما زال يحتوي placeholders لـCloudinary وX وSnapchat؛ ملفات EAS تحوي App/Apple IDs بديلة | وضع قيم الإنتاج عبر Secret Manager أو إعدادات CI، وعدم إضافتها للمستودع. |
| حرج | Redis في fallback | readiness العام يعلن fallback | تهيئة `REDIS_URL` لمزود مُدار وتشغيل اختبار load/WebSocket بعد التغيير. |
| حرج | Staging غير متاح | 21 ملف اختبار يعتمد API حي/مزودات خارجية | تجهيز MongoDB وRedis وCloudinary وOAuth وPush وAI في staging مع حسابات اختبار. |
| عالٍ | التحقق على أجهزة فعلية | لا يمكن إثبات الصوت/الكاميرا/Push/Safe Areas/CAPTCHA محليًا | تنفيذ مصفوفة iOS وAndroid وHuawei ومتصفحات فعلية. |
| عالٍ | متطلبات الشحن/الدفع الموثوق | تتطلب مزودًا معتمدًا وسياسة نزاعات واسترداد وWebhooks | اعتماد المزود والسياسات، ثم بناء التكامل واختباره في staging. |
| متوسط | تنظيف/ترحيل بيانات الإنتاج | لا توجد صلاحية لقاعدة البيانات الحية ولا يجوز تعديلها دون اعتماد | backup، مراجعة مخرجات dry-run، ثم تشغيل migration مصرح به. |

> **قرار الجاهزية:** الكود المحلي يمر بالفحوص الحتمية والبناء، لكن النسخة ليست مرشحة لنشر إنتاجي نهائي بعد. يجب إغلاق الحواجز الحرجة أولًا، ثم تشغيل E2E وload/security على Staging قبل الدمج والنشر.
