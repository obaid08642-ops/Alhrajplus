# تحقق إصلاحات المراسلة والمكالمات والترويج

**التاريخ:** 2026-08-20

## سبب إعادة الفحص

أظهر التحقق من الموقع الحي أن ملف JavaScript المنشور لا يتضمن نصوص سجل المكالمة أو زر مكبر الصوت أو صف `call-timeline` الموجود في مصدر GitHub. لذلك لا تُعد اختبارات المصدر أو رفع commit دليلًا على وصول الميزة إلى المستخدم. هذا التقرير يفرق صراحةً بين إصلاح المصدر واختبار البناء والتحقق الذي ما زال مطلوبًا من النسخة المنشورة والجهاز الفعلي.

## إصلاحات التشغيل

| المجال | الإصلاح المنفذ | النتيجة المقصودة |
|---|---|---|
| حالة الاتصال | أصبح `online` يتطلب نبض WebSocket حديثًا خلال 75 ثانية، ويُحوَّل الاتصال الخامل إلى `offline` مع تحديث `last_seen` وبث الحدث للمشتركين. | لا يبقى المستخدم متصلًا ظاهريًا بعد تعليق أو فقد التطبيق. |
| رسائل Mobile | صندوق إعادة الإرسال يعمل عبر REST كل 8 ثوانٍ حتى عند انقطاع WebSocket. | لا تتوقف الرسائل لأن websocket غير متصل مع بقاء HTTPS صالحًا. |
| رسائل Web | أضيف إجراء إعادة إرسال فعلي للرسالة الفاشلة باستخدام `client_message_id` ثابت. | لا تبقى علامة الفشل بلا إجراء، ولا ينشأ تكرار عند استجابة متأخرة. |
| سجل المكالمات | صف رسالة نظام دائم لكل مكالمة، بحالات جاري/منتهية/مرفوضة/فائتة ومدة محسوبة من الخادم. | يظهر الحدث داخل المحادثة بعد البث أو عند تحميل سجل المحادثة. |
| مكبر الصوت | زر مخرج الصوت موجود في Mobile، وأضيف في Web مع استخدام `setSinkId` حين يدعمه المتصفح وإظهار خطأ صريح عند عدم الدعم. | لا توجد دعوى تحكم زائفة في مخرج الصوت. |
| الترويج في Web | أضيف اختيار باقة وزر ترويج داخل أدوات مالك الإعلان في صفحة التفاصيل. | يستدعي `POST /listings/{id}/boost` مع مفتاح idempotency ويحدّث حالة الإعلان. |
| الترويج في Mobile | أضيف زر ترويج واختيار باقة داخل أدوات مالك الإعلان في صفحة التفاصيل. | يخصم Coins من Backend فقط بعد تأكيد الباقة ويعرض حالة مُروَّج. |

## فحص الإعلانات الشخصية

كانت ترويج الإعلانات موجودة في شاشة إعلاناتي ولكنها تعتمد على تحميل باقات الاقتصاد؛ أما صفحة تفاصيل الإعلان في Web وMobile فلم تحتوِ زر ترويج للمالك. تمت إضافة المسارين المفقودين واستخدام Endpoint الاقتصاد نفسه؛ لا توجد معاملة Coins محلية أو شكلية.

## التحقق المتبقي بعد النشر

الموقع الحي كان يقدم ملفًا ثابتًا أقدم من مصدر GitHub وقت الفحص؛ لذلك يلزم بعد نشر Web/Backend فحص ملف البناء الحي، ثم اختبار مستخدمين منفصلين: إرسال نص من الطرفين، انتظار تسليم وقراءة، تعليق أحد التطبيقين للتحقق من offline، مكالمة مقبولة ومكالمة غير مجابة، ثم ترويج إعلان يملك رصيد Coins كافيًا. تطبيق Mobile يحتاج إصدارًا أو تحديثًا فعليًا؛ إعداد EAS الحالي يتضمن `projectId` بديلًا وليس مشروعًا صالحًا للنشر الهوائي.
