# إتمام تحسين واجهة المكالمات Premium

## النطاق المنفذ

تم استبدال واجهة المكالمة المحدودة بتجربة موحّدة أعلى جودة في Web وMobile وفق النموذج المعتمد. لا يوجد زر تجميلي: كل عنصر تحكم ظاهر إما يرتبط بمسار مكالمة فعلي أو لا يظهر على المنصة غير الداعمة.

| الحالة أو التحكم | Web | Mobile |
|---|---|---|
| مكالمة واردة | شاشة كاملة تتضمن قبولًا ورفضًا، وترتبط بإشارات `call_answer` و`call_reject`. | شاشة كاملة تتضمن قبولًا ورفضًا داخل التطبيق؛ تؤجل إنشاء media/WebRTC حتى يختار المستخدم قبول المكالمة. |
| كتم الميكروفون | يغيّر `MediaStreamTrack.enabled` للمسار المحلي. | يغيّر المسار المحلي ويزامن كتم iOS مع CallKeep. |
| مكبر الصوت | غير معروض، لأن المتصفح لا يوفر تبديل مخرج صوت موثوقًا بين السماعة ومكبر الجهاز. | معروض على Android فقط ويرتبط بـCallKeep و`expo-audio`. يتولى iOS مسار الصوت من واجهة النظام. |
| العودة للمحادثة | تصغير حقيقي إلى شريط مكالمة مستمر؛ يبقى الاتصال قائمًا وتتاح استعادة الشاشة أو الكتم أو الإنهاء. | لا يُعرض زر شكلي. إدارة المكالمة في الخلفية ومسار الصوت تتبع واجهة النظام/CallKeep. |
| إنهاء المكالمة | يرسل `call_hangup` ثم ينظف WebRTC والصوت. | يرسل `call_hangup` وينهي CallKeep وينظف الصوت وWebRTC. |
| حالة الاتصال | حالة واضحة، مؤقت، وشارة «اتصال محمي» بعد الاتصال. | حالة واضحة، مؤقت، وشارة «اتصال محمي» بعد الاتصال. |

تحافظ Mobile على واجهة CallKeep عند الإمكان، لكن شاشة التطبيق لا تعتمد عليها وحدها: إذا تعذر فتح واجهة النظام، تظهر شاشة القبول والرفض الداخلية نفسها، وتبقى إشارات الرفض والقبول مرتبطة بالعقد الموثق.

## قيد التحقق المتبقي

لا يمكن لمحاكاة Metro أو اختبارات العقود تأكيد جودة الصوت أو السماح بالميكروفون أو تبديل مخرج الصوت على كل جهاز. يبقى اختبار مكالمة فعلية بين جهازين حقيقيين، أحدهما Android والآخر iOS إن أمكن، مطلوبًا قبل إطلاق واسع. هذا قيد تحقق مادي لا يعني وجود زر شكلي أو تعطل في مسار البناء.
