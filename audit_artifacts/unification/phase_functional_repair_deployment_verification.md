## تحقق Web الحي

أنشأ GitHub نشر Production بحالة `success`. فحص النطاق العام `https://www.alhraj.online` لا ملف `main` فقط، بل جميع ملفات JavaScript المعلنة في `asset-manifest.json`، أثبت وجود المعرفات التالية في chunks المنشورة:

| المعرف | الدلالة |
|---|---|
| `call-timeline-` | عرض سجل المكالمات داخل خط المحادثة |
| `boost-listing-detail-btn` | زر الترويج في صفحة تفاصيل الإعلان للمالك |
| `retry-message-` | إجراء إعادة إرسال الرسالة الفاشلة |

> كانت نتيجة الفحص السابقة لملف `main` وحده مضللة لأن صفحات المحادثة وتفاصيل الإعلان محملة كـchunks مستقلة. الفحص الحالي غطى جميع chunks المُعلنة، ولذلك يثبت وصول عناصر Web الجديدة إلى النطاق العام.

## ما لم يُدعَ أنه مكتمل

لا يمكن إثبات تبني Backend لكل commit من استجابة health الحالية، لأنها لا تعرض SHA نشر. كما لا يمكن اختبار إرسال حقيقي أو خصم Coins أو مكالمة بين مستخدمين في الإنتاج دون استخدام حسابات حقيقية، وهو أمر لم ينفذ لحماية بيانات الإنتاج. يجب بعد النشر إجراء اختبار ميداني بحسابين منفصلين وعلى جهاز Mobile فعلي، وتسجيل نتيجة كل حالة:

| التدفق | دليل النجاح المطلوب |
|---|---|
| إرسال رسالة | ظهورها لدى المستلم وتغير العلامة من إرسال إلى تسليم ثم قراءة |
| تعليق التطبيق | تحول presence إلى offline بعد مهلة النبض ثم online بعد العودة |
| مكالمة مقبولة | صف مكالمة واحد في المحادثة بمدة خادم غير صفرية بعد الإنهاء |
| مكالمة بلا رد | صف مكالمة فائتة بعد انتهاء المهلة |
| ترويج | اختيار باقة، خصم Coins مرة واحدة فقط، وتغير `is_boosted` في تفاصيل الإعلان وقائمة إعلاناتي |
