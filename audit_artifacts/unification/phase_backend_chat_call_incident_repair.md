# إصلاح حادثة المراسلة وسجل المكالمات في Backend

**التاريخ:** 2026-08-20

## الأدلة التشغيلية

أظهر سجل خدمة Backend أن WebSocket ومحادثات القراءة يعملان، لكنه لم يحتوِ على طلب `POST /api/chat/send` وقت التقاط السجل. كما أظهر خطأين عند بدء الخدمة في فهرسي `coins_ledger` و`wallet_transactions`: استخدم تعريف الفهرس الجزئي `$ne` مع `$type`، وهو تعبير غير مدعوم في MongoDB المستضاف.

اختبار غير مصادق عليه لمسار `POST /api/chat/send` عبر النطاق العام وعبر Render أعاد `401 Not authenticated`، وهي النتيجة الصحيحة التي تثبت أن توجيه POST وCORS يصلان فعليًا إلى Backend ولا يتحولان إلى 404 أو خطأ Vercel.

## السبب الجذري للمكالمة

كان Backend يشترط وجود وثيقة محادثة سابقة لكل إشارة مكالمة. إذا كانت المكالمة أول تفاعل بين الطرفين، يعيد التفويض `None` بصمت؛ فلا تصل دعوة المكالمة، ولا تنشأ `call_session`، ولا يمكن حفظ سجل المكالمة داخل الرسائل.

## الإصلاحات

| المجال | الإصلاح |
|---|---|
| دعوة مكالمة أولى | تنشئ `call_invite` محادثة ثابتة بين الطرفين عند غيابها، ثم تنشئ جلسة المكالمة وسجلها الدائم. |
| سجل المكالمة | يبقى موثقًا من `call_session` إلى رسالة نظام `system_type=call` للطرفين. |
| إرسال رسالة غير متصل | بعد إدراج الرسالة وتحديث المحادثة، يُشغّل الإشعار وPush في مهمة خلفية محمية؛ فشل الإشعار لا يعيد خطأ HTTP ولا يلغي الرسالة. |
| قابلية التشخيص | يضاف سجل آمن بعد حفظ الرسالة يحوي معرّف الرسالة والمحادثة والمرسل والمستلم فقط، من دون نص الرسالة. |
| فهارس MongoDB | أزيل `$ne` غير المدعوم من فهرسي idempotency الجزئيين، مع الإبقاء على قيد نوع النص لمنع أخطاء بدء الخدمة الموثقة. |

## التحقق

| البوابة | النتيجة |
|---|---|
| اختبارات Backend الشاملة | **121 passed** |
| اختبار رسالة دائمة رغم إخفاق مهمة الإشعار | ناجح |
| اختبار مكالمة أولى بلا محادثة سابقة | ناجح |
| حارس التعريب و`git diff --check` | ناجحان |

## اختبار ميداني بعد النشر

لا يمكن استخدام حسابات المستخدمين أو إنشاء رسائل إنتاجية تشخيصية دون إذن صريح. بعد النشر، ينبغي مراقبة سجل `[chat] message persisted` عند الضغط على إرسال؛ إذا لم يظهر، فالطلب لم يصل إلى Backend ويجب التقاط خطأ العميل. إذا ظهر السجل ثم بقيت الواجهة فاشلة، تكون الرسالة موجودة في MongoDB ويكون العطل في العميل أو مزامنة WebSocket، لا في الحفظ.
