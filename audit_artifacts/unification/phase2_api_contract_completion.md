# المرحلة 2 — توحيد عقود API وطبقات العملاء

## المنفذ

أضيف عقد عام، محدود وآمن، على `GET /api/meta/client-contract`. يعرّف الإصدار، اللغات الست، fallback العربية والسعودية، التقويم الميلادي، الأرقام الإنجليزية، ورؤوس السياق المشتركة. لا يحتوي العقد على أسرار أو تكوين استضافة أو صلاحيات إدارية قابلة للتنفيذ.

تستخدم طبقتا API الآن رؤوسًا موحدة في كل طلب:

| الرأس | Web | Mobile | الغرض |
|---|---|---|---|
| `X-Haraj-Language` | من `hp_lang` | من Secure/Async storage `hp_lang` | سياق اللغة الخادم. |
| `X-Haraj-Client` | `web` | `mobile` | قياس وحل اختلافات المنصة بصورة صريحة. |
| `X-Haraj-Contract-Version` | الإصدار نفسه | الإصدار نفسه | تشخيص توافق العميل مع الخادم. |

كلا العميلين يملك دالة lazy ومخزنة لجلب العقد، ويضيف Mobile تنسيق خطأ يستخرج FastAPI `detail` بصورة مطابقة لسلوك Web العملي. يظل `country_code` محميًا من الاستبدال ويستمر الإرفاق التلقائي في القناتين.
