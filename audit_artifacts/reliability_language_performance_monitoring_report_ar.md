# تقرير الاعتمادية واللغة والأداء والمراقبة

**المشروع:** الحراج بلس
**التاريخ:** 2026-08-19
**النطاق:** لغة الجهاز، التقويم، المكالمات، الأداء، Schema، ومراقبة API والفهرسة.

## الخلاصة التنفيذية

تم تصحيح أسباب واضحة في تجربة اللغة والتاريخ وواجهة المكالمات، وإضافة طبقة مراقبة تشغيلية إلى الخلفية ولوحة الإدارة. كما أضيف سياق Schema من نوع `BreadcrumbList` وربط `Product` بـ`WebPage`، لتحسين فهم الإعلان وعلاقته بمسار الموقع لدى محركات البحث وأنظمة الإجابة. لا يضمن ذلك مركزًا معينًا أو إدراجًا داخل جواب نموذج ذكاء اصطناعي؛ إنه يعالج شروط الصحة والوضوح والقابلية للقياس اللازمة للوصول إلى هذه التجارب.

## ما تم تنفيذه

### لغة الجهاز والتاريخ

أصبحت قائمة اللغة في Web تحتوي على خيار **«تلقائي (لغة الجهاز)»** في الشريط العلوي والإعدادات وشاشات الدخول. عند اختياره يُمسح العلم اليدوي وتعود اللغة إلى أول لغة مدعومة في تفضيلات الجهاز، مع fallback آمن إلى العربية. في Mobile أضيفت `expo-localization` واستخدمت أول لغة نظام أصلية، ثم `Intl` كبديل، ثم العربية كحل أخير.

أصبحت سياسة عرض التاريخ مركزية في Web وMobile. تستخدم لغة الجهاز لترتيب اليوم والشهر والسنة وعلامات الفصل، لكنها تفرض `calendar: gregory` و`numberingSystem: latn`. لذلك يبقى التاريخ **ميلاديًا** والأرقام `0–9`، حتى إذا اختار الجهاز تقويمًا هجريًا أو كانت الواجهة عربية.

### المكالمات

أزيلت من الواجهة الرسائل التقنية مثل «اتصال مباشر عبر STUN» وزر مخرج الصوت الذي يمكن أن يفشل بسبب قيود المتصفح. بقيت حالات مفهومة: «جاري الاتصال»، «المكالمة متصلة»، أو رسالة فشل عملية تطلب التحقق من الاتصال. أضيف متغير `TURN_ICE_SERVERS_JSON` إلى إعداد Render كي يمكن تزويد الخدمة بقائمة TURN حقيقية دون وضع credentials في المستودع.

> لا يمكن للكود وحده تحويل STUN إلى اتصال موثوق عبر جميع شبكات 4G/5G والشبكات المؤسسية. يلزم TURN server حقيقي ببيانات وقتية أو بيانات مستخدم/credential معتمدة، ثم إدخال JSON الخاص به في بيئة الإنتاج.

### الأداء

خُفّض التأخير الإجباري لشاشة البداية من **2.2 ثانية إلى 450ms**. بقي تقسيم الصفحات الثقيلة موجودًا. يوصى بعد النشر بإزالة المرور غير الضروري عبر proxy بين Vercel وRender عبر نطاق API مباشر في المنطقة الأقرب لمستخدمي الخليج، ومطابقة منطقة Mongo وRedis والخلفية، وإبقاء backend دائم التشغيل بالقدرة المناسبة. هذه إجراءات بنية تشغيلية وليست تغييرًا تجميليًا؛ وهي أهم من ضغط payload صغير عندما تكون استجابة التطبيق الداخلية بالميلي ثانية ويأتي التأخير من الشبكة/الاستضافة.

### Schema لـGEO وAEO

أضيف إلى كل صفحة إعلان عامة قابل للفهرسة:

| الإضافة | الغرض | شرط الصحة |
|---|---|---|
| `Product.@id` و`mainEntityOfPage` | ربط كيان الإعلان بعنوان الصفحة الأساسي مباشرة. | العنوان هو canonical الحالي للإعلان. |
| `BreadcrumbList` | توضيح مسار حقيقي: الحراج بلس → الفئة → الإعلان. | رابط الفئة موجود وقابل للتصفح، ويظهر المسار أيضًا في HTML. |
| Product/Offer الحالية | السعر، العملة، التوفر، حالة المنتج، الصور، المدينة وحقول الفئة. | تُنشأ من حقول البائع المنشورة فقط. |
| تحديث دورة الاكتشاف | sitemap وIndexNow والإزالة عند البيع أو الإيقاف. | لا تُعلن الإعلانات المخفية أو المباعة. |

تؤكد Google أن Product markup قد يؤهل الصفحة لطرق عرض أغنى لكنه لا يضمن عرضها؛ ويجب أن تكون معلومات السعر والتوفر والحالة متطابقة مع المحتوى المرئي.[1] كما يجب أن تمثل breadcrumbs مسارًا عاديًا حقيقيًا للمستخدم، لا مجرد بنية URL مصطنعة.[2]

### التنبيهات ولوحة Admin

أضيفت فحوص قراءة فقط تغطي Mongo وRedis و`/api/health` و`/robots.txt` و`/sitemap.xml` وصفحة إعلان عامة بعامل مستخدم بحث للتحقق من JSON-LD وBreadcrumb. تحتفظ الخدمة بسجل آخر 30 يومًا تقريبًا وتزيل الأقدم، مع فهرس زمني. تُرسل رسالة بريد إلى المشرف فقط عند التحول من سليم إلى متدهور/معطل، وعند عودة الخدمة، لتجنب الإغراق بالبريد.

أضيفت في Admin علامة **«المراقبة والتنبيهات»** تعرض الحالة، الفحوص الفاشلة والتحذيرات، P95 للمسارات داخل العملية، سجل آخر الحالات، وحالة إعداد البريد. زر «فحص الآن» ينفذ فحصًا يدويًا دون إرسال بريد مكرر.

## تشغيل التنبيه المجدول بعد النشر

أضيفت خدمة cron إلى `render.yaml` كل 5 دقائق. بعد مزامنة Blueprint في Render يجب إدخال الإعدادات التالية في لوحة البيئة:

| المتغير | أين يضبط | الاستخدام |
|---|---|---|
| `CRON_SECRET` | خدمة API وخدمة `haraj-platform-monitor` **بالقيمة نفسها** | حماية `/api/cron/monitoring` من الاستدعاء غير المصرح. |
| `RESEND_API_KEY` | خدمة API | إرسال التنبيه إلى البريد. |
| `MONITORING_ALERT_EMAIL` | خدمة API، اختياري | إن لم يحدد تستخدم الخدمة `ADMIN_EMAIL`. |
| `TURN_ICE_SERVERS_JSON` | خدمة API | قائمة TURN/STUN الحقيقية للمكالمات عبر الشبكات المقيّدة. |

توثق Render أن خدمة cron تعمل وفق cron expression، تضمن عدم تشغيل نسختين منها في الوقت نفسه، وتحاسب حسب وقت التشغيل مع حد أدنى معلن قدره **$1 شهريًا** لكل خدمة cron.[3] لا يحتوي المستودع على أي secret.

## قيود تحقق خارجي متبقية

يتطلب التحقق النهائي على أجهزة حقيقية بناء تطبيق Mobile جديدًا لأن `expo-localization` native module. كما يتطلب اعتماد المكالمات عبر شبكات مقيّدة إدخال بيانات TURN وتشغيل اختبار طرفين على Wi‑Fi و4G/5G. لا يمكن تفعيل خدمة Render cron أو البريد الفعلي من المستودع وحده؛ يجب مزامنة إعداد النشر ووضع قيم البيئة في لوحة Render.
